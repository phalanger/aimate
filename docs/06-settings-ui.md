# 设置界面梳理

## 一、现在什么样，问题在哪

两个地方用了同一种控件：一排按钮铺成网格，点一个算选中。

- **角色形象类型**：`orb / vrm / live2d / video / musetalk` 五个按钮
- **大模型提供商**：每个 provider 一个按钮

### 问题一：按钮网格用错了地方

按钮网格适合"少数几个平级选项，而且每个都想让用户看见"。这里两个场景都不是：

- 类型是**互斥的单选**，语义上就是下拉框
- 五个按钮横铺占掉一整行，把真正要填的字段挤到下面看不见
- provider 的数量还会增加，按钮网格会越铺越宽

### 问题二：字段没有跟着类型收起来

形象类型这块其实已经做了条件显示（`_renderAvatarTypes` 末尾那五行 `hidden`），
但**因为选择器本身占了一大块，视觉上仍然是"一堆设置摆在一起"**。大模型那边同理，
API key 已经会按 `needs_key` 隐藏，问题也主要出在选择器上。

所以要改的不是"加条件显示"，而是**把选择器换掉，并且让条件字段紧跟在选择器下面**。

### 问题三：换口型后端时改出来的三个 bug

这三个和上面是同一块代码，一起修：

1. **字段存反了。** `_captureAvatar()` 里：

   ```js
   this.avatar.talk_video = el("ed-talk-video").value;     // musetalk 模式下这个框是隐藏的 -> 空
   this.avatar.idle_video =
     this.avatar.type === "musetalk" ? el("ed-mt-video").value : el("ed-idle-video").value;
   ```

   MuseTalk 时代这是对的：那时 `ed-mt-video` 既是训练素材又是待机循环，**同一段视频**。
   换成 FlashHead 之后两者分家了——参考图是静态图，待机循环是视频——这段就把
   **参考图写进了 `idle_video`，`talk_video` 反而留空**。后果是：只要在界面上保存
   一次角色，手写的配置就被写坏。

2. **musetalk 那组没有待机视频选择框。** 界面上根本设不了 `idle_video`。

3. **资源扫描不认图片。** `server.py` 的 `scan("media", (".mp4", ".webm", ".mov", ".mkv"))`
   没有图片后缀，参考图在下拉框里出不来。

## 二、改成什么样

### 形象类型

```text
形象类型  [下拉: 抽象圆环 / 3D 模型 / Live2D / 真人循环视频 / 真人口型]
          <这一句说明选中的类型是什么、需要什么素材>
          ---------------------------------------------
          <只显示这个类型要填的字段>
```

各类型对应的字段：

| 类型 | 字段 |
| --- | --- |
| orb | 无 |
| vrm | VRM 模型、动作 |
| live2d | Live2D 模型 |
| video | 待机视频、说话视频 |
| musetalk | **待机视频**、**参考图**、形象 ID、准备形象 |

`musetalk` 这一行就是上面 bug 1 和 2 的修法：两个字段并列，各存各的。

### 大模型提供商

```text
提供商    [下拉: Ollama(本地) / Kimi / GLM / DeepSeek / 硅基流动 / Grok]
          <provider 的 hint>
          ---------------------------------------------
          接口地址
          API Key        <- 本地模型隐藏（已有的 needs_key 逻辑保留）
          模型
```

按钮上原来那个"key"角标改成下拉选项文字里的标记，选中后在 key 输入框的占位符里
说明是否已保存——这一条现在就是这么做的，不用改。

## 三、不改什么

- **条件显示的逻辑不重写。** 现有的 `hidden` 开关是对的，只是被选择器压住了。
- **配置格式不变。** `characters.json` 和 `providers.json` 的字段一个不动，
  否则现有配置要迁移。
- **通用设置区（`settings-generic`）不动。** 它是从 `config/settings.json` 生成的，
  加开关不需要写代码，这个设计是好的。

## 四、验证

改完要能确认的四件事：

1. 五种形象类型逐个选一遍，每次只出现该类型的字段
2. 存一个 musetalk 角色，`characters.json` 里 `idle_video` 是视频、
   `talk_video` 是图片——**这是 bug 1 的回归测试**
3. 参考图能在下拉框里选到
4. 本地和云端各选一个 provider，key 字段该藏的藏
