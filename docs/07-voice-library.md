# 音色库

## 一、现在什么样

角色编辑器里塞了一整条流水线：上传音频/视频 → 截取片段 → 语音识别 → 参考文本
输入框 → 保存。这些和"这个角色用哪个声音"是两件事，却混在一个对话框里。

数据上，一个"音色"其实是**一对**东西：

| 字段 | 存在哪 | 含义 |
| --- | --- | --- |
| `voice` | 角色 | 参考音频 wav 的路径 |
| `ref_text` | 角色 | 这段音频的**逐字文本** |

两者必须对应——声音克隆就是拿"这段音频 + 它说的话"去推断音色。但现在它们分开存
在每个角色上，于是：

- 两个角色想用同一个声音，要各写一遍参考文本
- 改了文本只改一个角色，另一个还是旧的
- 换个音频忘了改文本，就悄悄对不上了

### 一个已经存在的 bug

`ref_text` **只有编辑器在读写，从来没有传给语音流水线**。

切换角色时面板发的是：

```js
client.updateSession({ instructions: ..., voice: character.voice });
```

流水线那边 `_apply_session_voice_override()` 收到后设 `self.ref_audio = 新路径`，
但 `self.ref_text` 保持启动时 `services.json` 里 `--qwen3_tts_ref_text` 那一条不变。

也就是说：**换角色只换了音频，文本没换，克隆的依据是错位的。**
`web/js/realtime.js` 的 `buildSessionUpdate()` 也只认 `voice` 和 `instructions`
两个字段，没有传文本的通道。

## 二、改成什么样

### 数据

新增 `config/voices.json`，音色成为独立实体：

```json
{
  "voices": {
    "v-xiaoling": {
      "label": "小玲的声音",
      "file": "assets/voices/voice-ms4cu9tx.wav",
      "ref_text": "今天天气不错，我们出去走走吧。",
      "created": "2026-07-29"
    }
  }
}
```

角色只留一个引用：

```json
"voice_id": "v-xiaoling"
```

**兼容旧配置**：角色里如果只有 `voice` 和 `ref_text` 没有 `voice_id`，启动时按
文件路径归并成一个音色条目，自动补 `voice_id`。旧字段保留不删，这样万一要回退，
配置还是能用的。

### 界面

角色编辑器里只剩一行：

```text
声音   [下拉: 小玲的声音 / 林知的声音 / 默认(英文)]  [试听] [管理…]
```

「管理…」打开独立的**音色库**对话框，那条流水线整个搬进去：

```text
音色库
  ┌ 已有音色 ─────────────────────────┐
  │ 小玲的声音    5.0s   [试听] [改名] [删除] │
  │ 默认(英文)    5.0s   [试听]              │
  └───────────────────────────────────┘

  新建音色
    上传音频/视频  [选择文件]  起点[0] 时长[10]  [截取]
    参考文本       [                    ] [语音识别]
    名字           [                    ]
                                        [保存音色]
```

顺序就是实际要走的步骤，名字在最后填——和你说的一致：训练完再起名。

## 三、参考文本这件事，先把事实摆清楚

为什么音频能跟着切、文本不能：**启动参数是我们传的，运行时切换走的却是 OpenAI
Realtime 协议**，而那个协议里只有 `voice` 一个字段——它当初想的是"从预设音色里挑
一个"，没有"参考音频的逐字稿"这个概念。所以不是我们漏传，是协议里没这个位置。

Qwen3-TTS 自己的界面把这条规则写得很直白：

- 参考文本输入框：`Required if not set use x-vector only`（不勾 xvec_only 时**必填**）
- xvec_only 复选框：`仅用说话人向量，**效果有限**，但**不用传入参考音频文本**`

于是有两条路，各有代价：

| | 做法 | 代价 |
| --- | --- | --- |
| **A** | 打开 `qwen3_tts_xvec_only`（**我们自己的启动参数**，改一行配置） | 官方说"效果有限" |
| **B** | 改 `qwen3_tts_handler.py`，让它切音频时同步切文本 | 动 `site-packages`，重装会丢 |

「加载已保存的音色文件」那条路走不通：`qwen_tts` 有 `save_prompt`/`load_prompt`，
但 `speech_to_speech` 完全没有接这套，用它同样要改库。

**要紧的是：现在这个状态比两条路都差。** 当前 `xvec_only=False`（意味着文本必填
且必须对应），而实际用的文本是启动时那条——只要角色用的不是 `default.wav`，喂进
去的就是一段对不上的英文。所以选 A 大概率是**改善**，哪怕它绝对质量"有限"。

这个耳朵能听出来，值得直接试：A 只是一行配置，开了跑几句，不行就关。

## 四、做到哪了

**已完成**：音色成为独立实体（`config/voices.json`），角色只引用 `voice_id`；
上传/截取/识别/命名整条流程搬进独立的音色库对话框；旧配置按 clip 路径自动归并。

**还没做**：把音色烘焙成 `.pt` 音色包，以及为此需要的启动补丁。也就是说运行时
切角色仍然只换音频路径，参考文本仍是启动时那条——第三节说的问题还在，只是数据层
已经准备好了（音色里已经存着配对的文本，烘焙时直接拿来用）。

## 五、验证

1. 建一个新音色：上传 → 截取 → 识别 → 起名 → 保存，`voices.json` 里出现条目
2. 两个角色选同一个音色，`characters.json` 里都是 `voice_id`，文本只有一份
3. 旧配置（只有 `voice` + `ref_text`）打开后自动归并，声音不变
4. 删除一个正在被角色使用的音色，要有提示而不是让角色指向空
